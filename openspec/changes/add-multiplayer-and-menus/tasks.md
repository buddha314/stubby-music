## 3. Shared world state (host decides, D4)
- [x] 3.1 Collecting and sources (lightning bugs, plants, mines) (claimed: Claude). A joined client's harvest is a request on `stubby_net::HostChannel`; the host checks reach (`HOST_REACH`) and availability, depletes the source in the world's `SourceLedger` (moved out of the player's inventory: depletion is the world's) and sends the yields to that client alone (`GrantHarvest`). Depleted sources replicate to everyone, late joiners included, and return on the host's clock. Mines are machine production, so they come with the machines' state (3.5). Until 3.2, a client's inventory is its own: it checks for room before asking
- [x] 3.2 Inventory per player and shared storage, moves between them as host-checked requests (open question 1, settled) (claimed: Claude). The host keeps each remote player's `Pack` (inventory and recipe book), replicated to its owner alone and mirrored into its `PlayerInventory`; `SharedStorage` (48 boxes) replicates to everyone. Harvests, crafts and `StorageRequest`s from a joined client are the host's, by the single-player rules (`recipes_plugin::craft`, `StorageRequest::apply`); the client's recipes plugin stands aside (`DecidedElsewhere`), so nothing is applied twice. Tests: inventories private and host-kept, storage shared both ways with refusals, a craft made once from the host's pack. Storage became built barrels in 3.3 (the user's choice). **Not yet:** inventory changes made outside the recipes plugin (building, the rack, stream dismantling, goal deliveries) still change only a client's own copy until 3.3–3.5 (building and dismantling: done in 3.3)
- [x] 3.3 Building: streams and placed machines (claimed: Claude). Building, laying and dismantling are requests (`BuildRequest`, `LayRequest`, `Dismantle`), applied here or by the host, which checks reach, free ports and the plan's shape and pays from or refunds to the builder's pack. Built things carry a `Built` record and streams a `StreamRecord` (path points, part, upstream named by placed instance or stream key) that replicate; each peer shows them from the record and runs them locally. One peer counts built instances. **Storage is a built container** (user, 2026-11-27): the `storage_barrel` buildable (`store_boxes` 24, the homestead barrel) is a `Store` anyone may use, opened with E; the single shared store of 3.2 is gone. Tests: a barrel built through the host and used by three peers with refusals; streams laid from a burbler and a stream end, seen by a late joiner, and split by a dismantle everywhere. Not covered by a test: a joined client not also laying locally (the harness has no stream templates, so nothing is laid locally there; the guard is the crafting one's, which is tested). A joined client lays on from a new end by aiming at it again (the chained anchor waits for the host)
